# ESC/POS Preview

ESC/POS 명령어를 브라우저에서 미리 보는 도구. 영수증 프린터 없이 명령어가 어떻게 찍히는지 확인하고, 블록을 쌓아 명령어를 조립하거나, 명령어 원문을 붙여넣어 토큰 단위로 분석할 수 있다.

**Live Demo → https://rlnrlnworld.github.io/receipt-preview/**

## 배경

- **2025.07 — 프로토타입.** 실제 서비스에서 쓸 영수증 출력 모듈을 만들기 전에 ESC/POS 명령어 체계를 이해하려고 작성했다. 서비스용 영수증 생성 코드와 최소한의 파서(`ESC @`, `ESC a`, `ESC !`, `LF`)로 출력 결과를 눈으로 확인하는 용도였다.
- **2026.10 — 범용 도구로 마이그레이션.** 특정 서비스 의존 코드를 걷어내고 ESC/POS 명령어라면 무엇이든 넣어볼 수 있는 범용 미리보기로 재구성했다. 파서 명령어 커버리지 확장, 진단(Issues) 추가, 블록 조립 모드, hex 입력과 EUC-KR 디코딩, GitHub Pages 배포.

## 기능

### 두 가지 입력 모드 — 내용은 하나

| 모드 | 설명 |
|---|---|
| **조립** | 텍스트 · 구분선 · 피드 · 바코드 · 커트 블록을 쌓아 영수증을 만든다. 텍스트 블록은 정렬(좌/중/우)과 굵게 · 2배 · 밑줄 · 반전 토글을 가진다. `ESC @` 초기화 블록은 맨 앞에 고정. |
| **직접 입력** | 명령어 원문을 그대로 넣는다. `\x1B\x40` 이스케이프 문자열 또는 hex 덤프(`1B 40 ...`). hex는 UTF-8 / EUC-KR(CP949) 디코딩 선택 가능. |

모드를 전환해도 내용은 하나로 유지된다. 조립 → 직접 입력은 직렬화, 직접 입력 → 조립은 명령어를 블록으로 역변환한다. 블록으로 표현할 수 없는 명령(한 줄 안의 스타일 전환, 폭·높이 한쪽만 2배, CODE128 외 바코드 등)이 있으면 단순화되고 토스트로 알린다.

### 프리뷰

- **Preview** — 감열지 모양으로 렌더. 용지 폭 32 / 42 / 48 col 전환. 한글은 2칸, 영문·숫자는 1칸으로 실제 프린터와 같은 폭 계산 (Nanum Gothic Coding).
- **Tokens** — 명령어를 칩으로, 텍스트는 그대로 보여주는 토큰 뷰. 칩에 마우스를 올리면 오프셋과 원본 바이트.
- **Issues** — 파서 진단. 알 수 없는 명령, 유효하지 않은 인수, 바코드 길이 선언과 실제 데이터 길이 불일치 등.
- **Copy hex** — 현재 내용을 hex 덤프로 클립보드에 복사.

### 지원 명령어

| 명령 | 동작 |
|---|---|
| `ESC @` | 초기화 |
| `ESC a n` | 정렬 0 좌 · 1 중 · 2 우 |
| `ESC ! n` | 인쇄 모드 비트 (08 굵게 · 10 2배 높이 · 20 2배 폭 · 80 밑줄) |
| `ESC E n` · `ESC - n` | 굵게 · 밑줄 |
| `ESC d n` · `ESC J n` | n줄 · n도트 피드 |
| `ESC i` · `ESC m` · `GS V m [n]` | 커트 |
| `GS B n` | 흑백 반전 |
| `GS ! n` | 글자 크기 |
| `GS h n` · `GS w n` · `GS H n` | 바코드 높이 · 모듈 폭 · HRI 위치 |
| `GS k m …` | 바코드 (NUL 종료형 / 길이 지정형 모두) |
| `ESC t` · `ESC M` · `ESC 2` · `ESC 3` · `ESC p` | 인식만 함 (렌더 영향 없음) |

전체 목록은 앱 헤더의 **명령어** 버튼. 바코드는 스캔 가능한 실제 심볼이 아니라 데이터에서 결정적으로 생성한 시각적 대역이다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/
```

Vite 7 + TypeScript, 런타임 의존성 없음. 입력 상태는 localStorage에 저장된다.

## 구조

```
src/
  main.ts                 UI · 상태 · 모드 전환 · 토스트
  utils/
    escposParser.ts       ESC/POS 문자열 → 노드 트리 + 토큰 + 진단, 렌더러
    decodeInput.ts        이스케이프 문자열 / hex 덤프 → 바이트, 텍스트 인코딩
    blocks.ts             조립 블록 타입, 블록 ⇄ 명령어 직렬화/역변환, 데모
  tokens.css              디자인 토큰 (OKLCH)
  style.css               레이아웃 · 컴포넌트
```

파서는 바이트 버퍼가 아닌 문자열 위에서 동작한다. `TextEncoder`를 거치면 `\xFF` 같은 제어 인수가 UTF-8 두 바이트로 늘어나 명령어 파싱이 깨지기 때문이다. hex 입력은 바이트를 latin1로 1:1 매핑한 뒤, 텍스트 구간만 선택한 인코딩으로 다시 디코딩한다.

## 배포

`main` 브랜치에 push하면 GitHub Actions가 빌드해서 GitHub Pages에 배포한다 (`.github/workflows/pages.yml`). Pages 경로용 `base`는 빌드 시 `GITHUB_PAGES=1` 환경변수로만 적용되어 로컬 개발과 다른 호스팅에는 영향이 없다.
