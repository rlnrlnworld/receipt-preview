# 🧾 ESC/POS Preview

영수증 프린터 없이 ESC/POS 명령어가 어떻게 찍히는지 브라우저에서 바로 보는 도구.

👉 **Live Demo: https://rlnrlnworld.github.io/receipt-preview/**

## 왜 만들었나

2025년 7월, 서비스에 들어갈 영수증 출력 모듈을 짜기 전에 ESC/POS가 뭔지부터 알아야 했다. 명령어 문서만 봐서는 감이 안 와서, 명령어 문자열을 넣으면 HTML로 그려주는 파서를 하나 뚝딱 만들었다. `ESC @`, `ESC a`, `ESC !`, `LF` 네 개만 알아듣는 수준이었고 서비스용 영수증 생성 코드가 같이 들어있는 프로토타입이었다.

2026년 10월에 다시 꺼내서 범용 도구로 손봤다. 서비스 전용 코드는 다 걷어냈고, 어떤 ESC/POS 명령어든 붙여넣거나 블록으로 조립해서 확인할 수 있게 바꿨다. 파서가 알아듣는 명령어도 늘렸고 못 알아듣는 건 왜 못 알아듣는지 알려준다.

## 할 수 있는 것

### ✍️ 두 가지 입력 방식, 내용은 하나

**조립** — 텍스트 · 구분선 · 피드 · 바코드 · 커트 블록을 쌓는다. 텍스트 블록마다 정렬이랑 굵게 / 2배 / 밑줄 / 반전 토글이 붙어 있다. 맨 앞 `ESC @` 초기화는 고정.

**직접 입력** — 명령어 원문을 그대로 넣는다. `\x1B\x40` 식 이스케이프 문자열이든 `1B 40 ...` hex 덤프든 상관없다. hex는 텍스트 구간을 UTF-8이나 EUC-KR로 풀어볼 수 있다.

둘 사이를 오가도 내용은 하나다. 조립한 걸 직접 입력으로 넘기면 명령어가 되고, 직접 입력한 걸 조립으로 넘기면 블록으로 돌아온다. 다만 블록으로 못 담는 게 있다 — 한 줄 안에서 스타일이 바뀐다거나, 폭만 2배라거나, CODE128이 아닌 바코드 같은 것들. 그런 건 가장 가까운 형태로 단순화하고 토스트로 알려준다.

### 👀 보는 방법

- **Preview** — 감열지처럼 그려준다. 용지 폭은 32 / 42 / 48 col. 한글 2칸, 영문 1칸으로 실제 프린터랑 똑같이 줄바꿈된다.
- **Tokens** — 명령어는 칩으로, 텍스트는 글자 그대로. 칩에 마우스 올리면 오프셋이랑 원본 바이트가 뜬다.
- **Issues** — 파서가 걸러낸 것들. 모르는 명령어, 이상한 인수, 바코드 길이를 22바이트라고 선언해놓고 8바이트만 넣은 경우 같은 거.
- **Copy hex** — 지금 내용을 hex 덤프로 복사.

### 📋 알아듣는 명령어

| 명령 | 뭐 하는 건지 |
|---|---|
| `ESC @` | 초기화 |
| `ESC a n` | 정렬 — 0 좌, 1 중, 2 우 |
| `ESC ! n` | 인쇄 모드 비트 — 08 굵게, 10 2배 높이, 20 2배 폭, 80 밑줄 |
| `ESC E n` / `ESC - n` | 굵게 / 밑줄 |
| `ESC d n` / `ESC J n` | n줄 / n도트 피드 |
| `ESC i` / `ESC m` / `GS V m [n]` | 커트 |
| `GS B n` | 흑백 반전 |
| `GS ! n` | 글자 크기 |
| `GS h n` / `GS w n` / `GS H n` | 바코드 높이 / 모듈 폭 / HRI 위치 |
| `GS k m …` | 바코드 — NUL 종료형이랑 길이 지정형 둘 다 |
| `ESC t` `ESC M` `ESC 2` `ESC 3` `ESC p` | 인식은 하는데 화면엔 영향 없음 |

앱 헤더의 **명령어** 버튼 누르면 같은 표가 나온다. 바코드는 진짜 스캔되는 심볼은 아니고 데이터로 모양만 만든 거라는 점은 참고.

## 🚀 돌려보기

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/
```

Vite 7 + TypeScript. 런타임 의존성은 없다. 입력한 내용은 localStorage에 남아서 새로고침해도 유지된다.

## 🗂 파일 구조

```
src/
  main.ts                 UI, 상태, 모드 전환, 토스트
  utils/
    escposParser.ts       ESC/POS 문자열 → 노드 트리 + 토큰 + 진단, 그리고 렌더러
    decodeInput.ts        이스케이프 문자열 / hex → 바이트, 텍스트 인코딩
    blocks.ts             조립 블록 타입, 블록 ⇄ 명령어 변환, 데모 데이터
  tokens.css              디자인 토큰 (OKLCH)
  style.css               레이아웃이랑 컴포넌트
```

파서는 바이트 배열이 아니라 문자열 위에서 돈다. 처음 만들 때 `TextEncoder`로 바이트를 뽑았는데, `\xFF` 같은 제어 인수가 UTF-8 두 바이트로 늘어나면서 `GS B \xFF`가 깨지는 걸 보고 바꿨다. hex 입력은 일단 latin1로 1:1 매핑해서 파싱한 다음 텍스트 구간만 고른 인코딩으로 다시 디코딩한다.
